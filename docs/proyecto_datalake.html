2. Arquitectura

2.1 Flujo de Datos (Medallion Architecture)

Los datos fluyen de izquierda a derecha a través de capas con calidad creciente:

  1. Fuentes → APIs, Bases de Datos, IoT, Archivos Batch, Eventos
  2. Ingesta → API Gateway + Lambda (online), MSK Kafka (streaming), EKS (batch), S3 Landing (offline)
  3. Bronze (Raw) → Datos crudos sin modificar, organizados por fecha
  4. Silver (Curated) → Datos limpios, deduplicados, tipados, formato Parquet
  5. Gold (Augmented) → Datos enriquecidos, agregados, KPIs, features ML
  6. Consumo → Athena (SQL), Redshift (BI), SageMaker (ML), Bedrock (GenAI), APIs

2.2 Landing Zone

Punto de aterrizaje exclusivo para datos batch/offline. Cuando llega un archivo:

  1. S3 Event Notification dispara Lambda
  2. Lambda valida formato y tamaño
  3. Copia a Bronze con prefijo de fecha (year/month/day/)
  4. Dispara Glue Crawler para actualizar catálogo
  5. Datos en Landing se mueven a Glacier a los 30 días y expiran a los 365

3. Seguridad y Compliance

3.1 Protección de Datos

  • KMS: Llave con rotación anual. Encripta S3, Redshift, ECR, Neptune
  • Macie: Escaneo semanal de PII en Bronze/Silver/Gold
  • Bedrock Guardrails: Bloquea SSN, tarjetas, llaves AWS. Anonimiza emails, teléfonos, IPs
  • S3: Encriptación AES256, bloqueo público, versionado

3.2 Seguridad de Red

  • WAF: Rate limiting (2000 req/5min), SQL Injection, OWASP rules
  • Security Groups: Acceso restringido por CIDR a Redshift, Neptune, MSK
  • VPC: Todos los servicios con VPC requieren subnet_ids (opcional, se configura después)

3.3 Auditoría

  • CloudTrail: Todas las acciones API registradas, validación de integridad
  • AWS Config: Reglas: S3 encriptado, S3 no público
  • GuardDuty: Detección de amenazas en S3, K8s, malware

6.3 Despliegue

Requisitos previos:

  • Terraform >= 1.3.0
  • AWS CLI configurado con credenciales
  • Cuenta AWS con permisos administrativos

Pasos:

  1. git clone [repositorio interno]
  2. cd bnxlakehouse
  3. cp terraform.tfvars.example terraform.tfvars → completar valores
  4. terraform init
  5. terraform plan
  6. terraform apply (sin VPC: solo servicios serverless)
  7. Agregar VPC cuando esté lista: terraform apply -var='vpc_id=vpc-xxx' -var='subnet_ids=["subnet-a","subnet-b"]'

Deploy solo sistema de costos:

./deploy_costs.sh
